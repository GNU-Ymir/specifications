\section{YIL language}
\label{sec:basics:yil_language}

Ymir is a high level language: one statement of it can stand for a good many
machine instructions. That is convenient to write and awkward to reason about,
because the cost of a line -- how much memory it touches, how many times it
copies a value -- is exactly what the high level form hides. C sits closer to the
machine and is often used to make that cost visible; this book uses a language
closer still.

That language is YIL, the Ymir Intermediate Language, and it is what the compiler
itself works on. It comes in two levels. L-YIL, \textit{low} YIL, is the flat
form: no loops, no scopes, nothing the machine does not have. M-YIL,
\textit{middle} YIL, keeps the structure a programmer recognises -- loops, and
some of the memory management -- while already being explicit about what the
source code left implicit. The two are rarely needed at once, so most of the book
simply says YIL; where the distinction matters, the names L-YIL and M-YIL are
used.

The \textit{hello.yr} file of Listing~\ref{lst:basics:hello_world} becomes the
two representations below. Nothing in them needs to be understood yet -- they are
here to show what the rest of the book will be pointing at. The YIL listings are
simplified for readability: they keep the structure of what the compiler prints
and drop some of the internal annotations it emits.

\begin{lstlisting}[style=myilVerb, caption=M-YIL representation of \textit{hello.yr}]
frame : [weak] std::io::println!{[c8]}::println (a(#8h) : [c8])-> void {
    std::io::print (a(#8h));
    std::io::putchar ('\n'c8);
    <unit-value>
}
frame : hello::main ()-> void {
    std::io::println!{[c8]}::println ("Hello World!"s8);
    <unit-value>
}
\end{lstlisting}

\begin{lstlisting}[style=lyilVerb, caption=L-YIL representation of \textit{hello.yr}]
frame :  [weak] _Y3std2io7printlnNS2c8FS2c8Zv (let a(#1) : (len-> u64, ptr-> *(u8)))-> void {
    _Y3std2io5printFS2c8Zv(a(#1));
    putchar(10);
}
frame :  _Y5hello4mainFZv ()-> void {
    _Y3std2io7printlnNS2c8FS2c8Zv((len-> 12, ptr-> "Hello World!"));
}
frame :  main (let argc(#1) : u32, let argv(#2) : *(void))-> i32 {
    _yrt_run_main(argc(#1), argv(#2), &_Y5hello4mainFZv);
    return 0;
}
\end{lstlisting}

Nobody writes YIL. The compiler produces it, and nothing reads it back: there is
no tool that turns its printed form into an executable. It is a window onto the
compiler, not a language to program in. The option \token{-fdump-ymir} opens that
window, writing out a set of intermediate files, of which \textit{.ydump-sem}
holds the M-YIL and \textit{.ydump-yil} the L-YIL of the source file compiled.

\begin{lstlisting}[style=bashVerb, escapechar=@+]
@+\textcolor{teal!80}{alice@dev:\mtilde}@+$ gyc -fdump-ymir hello.yr -o hello
@+\textcolor{teal!80}{alice@dev:\mtilde}@+$ ls
@+\textcolor{green!70!black}{hello}@+
hello.yr
hello.yr.ydump-decls.1
hello.yr.ydump-decls.2
hello.yr.ydump-opt
hello.yr.ydump-sem
hello.yr.ydump-yil
\end{lstlisting}
