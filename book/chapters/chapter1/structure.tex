\section{How this book is structured}
\label{sec:(chap1):structure}

This book is organized in chapters, each of them presenting a set of related
notions. Every notion is introduced at the point where it is needed, so the
chapters are meant to be read in order. Each chapter ends with a series of
exercises, followed by their solutions.

Two kinds of pages are used. The pages on a white background contain the course
itself, and are the ones to read on a first reading. The pages on a light gray
background contain the specification of the language, and describe in a more
formal and more detailed way the notions presented in the course. They can be
skipped on a first reading, and read later on when a precise answer is needed.

Source code is presented in listings. Each listing names the language in which
its code is written by a badge placed in its top right corner, and by the color
of its background.

\begin{description}
\item[\ymirbadgeymir] \fcolorbox{black!35}{background!40}{\phantom{MM}}~a
  \textbf{yellow} background, for source code written in the Ymir language. This
  is by far the most common listing of the book.
\item[\ymirbadgemyil] \fcolorbox{black!35}{teal!10}{\phantom{MM}}~a
  \textbf{teal} background, for M-YIL code, and
  \fcolorbox{black!35}{olive!10}{\phantom{MM}}~a \textbf{green} one, for L-YIL
  code. These two languages are not written by the programmer, they are
  generated by the compiler, and are used in this book to describe what a Ymir
  program actually does once compiled. They are presented in
  Section~\ref{sec:(chap1):yil_language}.
\item[\ymirbadgeshell] \fcolorbox{black!35}{gray!10}{\phantom{MM}}~a
  \textbf{gray} background, for a terminal session. The lines starting with a
  prompt of the form \tokennolst{alice@dev:\mtildeascii{}\$} are commands typed
  by the user, and the lines that follow them are the output of those commands.
\end{description}

Some listings present a program that is deliberately wrong, in order to explain
why the compiler rejects it. Such a listing is written in the Ymir language as
any other, but its badge is a warning sign, \ymirbadgeerror. Two
highlights are then used inside the listing: the color \hb{red} marks the part
of the code that is at fault, and the color \hcb{green} marks a correction that
has been applied to it.
